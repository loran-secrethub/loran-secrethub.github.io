Worktext Studio

A browser tool I built so my team can preview, check and review worktext pages before they're rendered to PDF, instead of going through repeated render, review, render rounds.

By Loran Iñosa, a former teacher who now builds e-learning and the tools behind it. Read my journey

My role
Created it and keep improving it
Users
IDs, AOs and LXDs on my team
Type
Browser app, hosted on GitHub Pages
Built with
HTML · CSS · JavaScript · Google Sign-In · Apps Script · Google Sheets

The problem

Worktexts are written as HTML and then rendered into PDF. Layout problems, such as a page running too long or an image that's too big, only showed up after rendering.

Fixing them meant repeated render, review, render cycles between the IDs, AOs and LXDs on my team.

Why I built it

Catch layout problems while editing, not after rendering.

Who uses it

IDs, AOs and LXDs on my team use Worktext Studio while building and reviewing worktexts: reviewers leave comments on the page, and developers work through them before the PDF is made.

How it started

A simple preview page. Every new feature came from watching how my team used it.

Key features

  • Overflow check

    Measures each page against a 990px ceiling and flags the ones that run over. A sidebar shows every page's height at a glance.

  • PDF Simulation

    Imitates the PDF renderer with four profiles: K-G3, G4-G6, Bible Subject and Teacher's Manual.

  • Sticky-note reviews

    Comments pinned to text or images, which reviewers can drag, collapse, copy, link and delete.

  • Comments that follow content

    When the HTML is edited, comments stay attached and show where they moved from ("Moved from page X").

  • Review mode

    Places the Google Doc beside the worktext, so reviewers can compare the two side by side.

  • Shared comments

    Signed-in teammates see the same comments, with authors, times, replies and a Done status.

Under the hood

Worktext Studio is a client-side web app: most of its logic runs in the browser. For shared comments, it uses Google Sign-In for identity, a Google Apps Script web app as a lightweight serverless back end, and a Google Sheet as a simple data store. It's hosted on GitHub Pages, and every service it uses is free.

In the browser · Front end

  • Live preview, PDF Simulation and overflow checks
  • Sticky notes and comments that follow edited content
  • Review mode with the Google Doc side by side
  • PDF export through the print dialog
  • Save Reviewed HTML: comments embedded in a local file, no server needed

On Google's free services · Back end

  • Sign in with Google, set up through a Google Cloud project
  • Apps Script checks the sign-in, then reads and writes shared comments
  • A Google Sheet stores comments, grouped by lesson code

Decision

Free Google services instead of a paid server. My team already had company Google accounts, so sign-in was free and familiar.

Designed for the people using it

  • Two modes: Revise & Check for fixing pages, Review for comparing with the Google Doc.
  • Safeguards: Save Reviewed HTML won't save without a comment, never overwrites the original file, and deleting asks for confirmation.
  • Light and dark themes for long working sessions.
  • Chloe: a small companion who sends encouraging messages while you work.

A teacher's detail

Review work can be tiring. A little encouragement helps.

Results

Worktext Studio is used by my team in production.
